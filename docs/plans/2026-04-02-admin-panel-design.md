# 爱宠家 (PawHome) 网页管理端设计文档

## 1. 概述
根据现有微信小程序（爱宠家）的业务范围与 `小程序网页管理端需求与架构文档.md`，本项目旨在为小程序提供一个完整的后台管理系统。
**核心原则**：功能设计严格按照现有小程序范围实现，不画蛇添足。主要包含：基础仪表盘、用户管理、内容管理（帖子/评论）、商城管理（商品/订单）、服务管理（疫苗/服务机构）、系统基础设置。

## 2. 技术架构调整
经确认，对原定技术栈进行调整：
- **前端架构**：
  - 框架：Vue 3 (Composition API, `<script setup>`)
  - 路由：Vue Router 4
  - 状态管理：Pinia
  - UI 组件库：Element Plus
  - 构建工具：Vite
  - HTTP 客户端：Axios
- **后端架构**：
  - 框架：继续复用现有的 Flask 微服务
  - 数据库：继续使用现有的 SQLAlchemy ORM (目前为 SQLite，后续按需迁移)
  - 接口隔离：在 `backend/app/api/v1/` 下新增 `admin/` Blueprint 进行管理端 API 隔离。
  - 鉴权机制：复用并扩展现有的 JWT 认证体系，新增 `@admin_required` 装饰器。

## 3. 数据库扩展设计
在复用现有业务模型（如 `User`, `Post`, `ShopProduct`, `ServiceAppointment` 等）的基础上，新增管理端特有的数据模型：
1. **AdminUser**: 管理员账号表（用户名、密码哈希、姓名、角色、状态等）。
2. **AdminRole & RolePermission**: 角色与权限映射表（用于实现 RBAC）。
3. **AdminLog**: 操作审计日志表。
4. **SystemConfig**: 基础系统配置项（如轮播图配置，如果小程序用到）。

## 4. 纵向切片式开发计划 (Vertical Slices)

采用纵向切片（端到端）的敏捷迭代开发模式，共分为 4 个主切片：

### 切片 1: 基础设施与基础认证 (Auth & Layout)
- **目标**：搭建前后端基础工程框架，跑通登录与权限拦截。
- **后端**：
  - 创建 `AdminUser` 及相关模型，编写数据库迁移/初始化脚本（注入默认超级管理员账号）。
  - 实现 `/api/v1/admin/auth/login` (登录接口，下发 Token)。
  - 实现 `@admin_required` 权限装饰器。
- **前端**：
  - `npm create vite@latest admin-panel -- --template vue-ts`
  - 安装 Element Plus, Vue Router, Pinia, Axios。
  - 实现 Axios 拦截器处理 401 登出。
  - 开发登录页 (`Login.vue`) 和基础的带侧边栏与面包屑的后台布局 (`Layout.vue`)。

### 切片 2: 用户与内容管理 (Users & Content)
- **目标**：实现对小程序最核心的用户与社区帖子的管控。
- **后端**：
  - 提供 `/api/v1/admin/users` (分页查询用户、查询详情、封禁/解封用户)。
  - 提供 `/api/v1/admin/posts` (分页查询帖子、审核、删除) 和 `/comments` (删除评论)。
- **前端**：
  - **用户管理页**：表格展示用户基础信息（头像、昵称、注册时间），支持禁用/启用操作。
  - **帖子管理页**：表格展示社区帖子（缩略图、作者、内容摘要），支持快速审核或下架/删除。
  - **评论管理页**：展示用户评论，提供删除违规评论的按钮。

### 切片 3: 商城与服务管理 (Shop & Services)
- **目标**：支撑小程序的电商交易与线下服务预约。
- **后端**：
  - 商城：开发针对 `ShopProduct` 的 CRUD（新增商品、图片上传、上下架），针对 `ShopOrder` 的状态流转（特别是发货与退款）。
  - 服务：开发针对 `ServiceProvider` (服务机构) 和 `ServiceAppointment` (预约记录) 的查询与状态变更。
- **前端**：
  - **商品管理页**：复杂的表单（支持富文本/多图上传）用于录入商品，表格用于上下架管理。
  - **订单管理页**：按状态（待支付、待发货等）筛选订单，实现“发货”弹窗（录入物流信息）。
  - **服务预约管理页**：展示用户在小程序的预约记录，提供“确认预约”或“取消预约”的后台操作。

### 切片 4: 仪表盘与系统设置 (Dashboard & System)
- **目标**：完善全局统计与系统安全性。
- **后端**：
  - 统计 API：提供今日新增用户、订单总额、帖子总数等聚合数据。
  - 系统 API：提供管理员账号管理、日志查询 API。
- **前端**：
  - **仪表盘页**：集成 ECharts，将统计数据可视化（如订单趋势图）。
  - **管理员设置页**：对内部账号进行增删改查。
  - **操作日志页**：展示内部人员的操作审计记录。

## 5. 测试与验收标准
1. **端到端完整性**：每一个切片完成后，管理端的操作必须能即时反映在数据库中，并影响小程序的正常展现（如后台下架商品，小程序不再显示）。
2. **前后端解耦**：完全通过 JSON API 通信。
3. **安全性**：所有 `/api/v1/admin/*` 接口必须受到 JWT 及 RBAC 的保护，防止未授权访问。
