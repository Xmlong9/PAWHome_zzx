## 背景

现有 `/pages/search/index` 同时承载“社区搜索”和“商店搜索”，但社区搜索仅能按关键词拉取 `GET /search/posts`，分类/排序 UI 不生效、无分页、结果不可点击跳转，且历史记录不持久化。需求为：商店搜索与社区搜索分离；主页与社区共用同一套“社区搜索”。

## 目标

- 主页与社区入口统一跳转到 `type=community` 的搜索页，展示社区内容搜索。
- 商城入口跳转到 `type=shop`，展示商品搜索。
- 社区搜索支持：关键词、分类（猫/狗/全部）、排序（综合/最新）、分页上拉加载、点击进入帖子详情。
- 搜索历史按搜索类型分开持久化，支持单条删除。

## 非目标

- 不实现“话题/用户”搜索。
- 不做复杂筛选（价格、品牌等）或高级排序策略。

## 方案

### 页面与路由

- 复用现有页面：`/pages/search/index`
- 通过 query 参数 `type` 区分：
  - `type=community`：社区搜索
  - `type=shop`：商店搜索

### 社区搜索数据流

- 输入关键词触发搜索：重置 `page=1`，清空结果，发起请求。
- 切换分类/排序：同样重置 `page=1`，重新请求。
- 上拉触底：若 `hasMore` 且非 `loading`，`page+1` 追加拉取。

### 后端接口

- 复用 `GET /search/posts`，扩展参数：
  - `type=all|cat|dog`：映射 `Post.post_type`
  - `sort=hot|latest`：
    - hot：按 `like_count + comment_count + favorite_count` 倒序
    - latest：按 `created_at` 倒序
- 可见性：遵循帖子可见性规则，仅返回当前用户可见的帖子。

### 前端接口封装

- `searchCommunity(q,page,pageSize,{type,sort})` 透传参数到 `GET /search/posts`。

### 兼容与错误处理

- 请求失败：toast 提示并清空结果（保持用户可重试）。
- `type` 非法值：后端按 “不过滤/默认排序” 处理；前端分类映射只输出受支持值。

## 验收

- 社区搜索：关键词搜索可返回结果；切换综合/最新能改变排序；切换猫/狗能过滤类型；上拉能分页加载；点结果进入帖子详情。
- 主页与社区入口进入搜索页表现一致（均为社区搜索）。
- 搜索历史在再次进入页面时可恢复，且社区/商店互不干扰。
