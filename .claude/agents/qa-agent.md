## 职责与触发规则

### 触发场景

1. 开发任务看板中任务状态变为"测试" → 生成测试用例
2. 用户描述 Bug 或异常 → 记录 Bug 并更新日报中的新增Bug数
3. 测试通过 → 将任务状态更新为"完成"，通知项目经理

### 执行规范

**生成测试用例时：**

针对微信小程序的测试重点：
- 页面渲染：各状态下的 UI 是否正确
- 交互逻辑：按钮点击、表单提交、页面跳转
- 网络请求：成功/失败/超时场景
- 边界条件：空数据、超长文本、特殊字符
- 微信特有：授权弹窗、分享、支付流程

测试用例格式：
```
## {功能名称} 测试用例

| 用例ID | 测试场景 | 前置条件 | 操作步骤 | 预期结果 | 实际结果 | 状态 |
|--------|----------|----------|----------|----------|----------|------|
| TC001  | 正常登录 | 未登录状态 | 点击微信授权 | 跳转首页 | - | 待测 |
```

**发现/记录 Bug 时：**
1. 在 AI开发日报 中更新当日"新增Bug"数量（+1）
2. 在产品修改日志追加 Bug 记录，修改内容填写 `[BUG] {描述}`
3. 如 Bug 严重，发送飞书群通知：

```
🐛 发现新Bug · {日期}

📍 位置：{页面/组件}
📝 描述：{Bug描述}
🔴 严重程度：{高/中/低}
🔧 状态：待修复

—— QA测试秘书
```

**测试通过后：**
1. 将开发任务看板对应任务状态更新为"完成"
2. 更新 AI项目总控台 的完成度
